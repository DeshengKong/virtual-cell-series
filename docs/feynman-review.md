# 费曼审核规范

每期脚本定稿前必须通过下面的审核。审核者只拿到他那个角色本来能拿到的东西，不拿到作者的解释，避免被作者的思路带偏。谁拿什么、怎么调用，见 `docs/agents.md`；提示词在 `.claude/agents/`。

## 审核一：新生复述（模拟观众，两个人）

**追更的新生**（`freshman-follower`）：高中生物和数学水平，从第 1 期一路看下来。给他本期脚本和**之前各期的脚本全文**（不是一句话总结：真观众看过的是全片）。

**路过的新生**（`freshman-dropin`）：同样的水平，之前一期都没看过，只听不看。只给他去掉画面提示的本期解说词（`tools/strip_cues.py`）。很多观众是从中间某一期点进来的，也有很多人只听不看。

要求他们：
1. **复述**：不看脚本，用自己的话把这期讲的核心讲给一个同学听。复述错了或漏掉核心，这期就不通过。
2. **揭晓前的猜测**：每一处"先猜一下"，先写下猜测和理由再往下读。**这是模拟新生最有用的信号**：猜对了且理由就是脚本要讲的，说明悬念不成立；猜错的方向说明观众带着什么误解进来。
3. **卡点**：逐段标出哪一句听不懂、哪一句要倒回去重听、哪个词不认识。
4. **没回答的"为什么"**：听完后心里还剩哪些"为什么"。
5. **注意力**：哪一段最想快进，哪一段最有意思。

模型装不出"不知道"，所以复述通过只是弱证据；卡点和猜测比复述可信。

## 审核二：费曼标准审核（`feynman-reviewer`）

依据《费曼物理学讲义》的讲法，逐条检查：

1. **名字不等于理解。** 每个术语出现前，观众是否已经知道它指的是什么、能做什么？先有东西，后有名字。
2. **每个"是什么"都要有"为什么"或"怎么知道的"。** 不允许无理由的断言；确实只能告知的事实（如测量数据），要说明是测出来的、怎么测的。
3. **从看得见、摸得着的东西出发。** 具体例子在前，抽象概括在后。
4. **类比必须说清在哪里失效。** 只给类比不给边界，等于埋下误解。失效处记入 `docs/concepts.yml` 的 `fails`。
5. **简化可以，说错不行。** 简化后的说法必须是"低分辨率下仍然正确"，而不是"方便理解但其实是错的"。
6. **诚实区分已知与未知。** 已证实、有争议、没人知道，三者不能混。每个数字和说法带来源：设定的 / 算出来的 / 测出来的 / 还不知道。
7. **前置闭合。** 本期用到的每个概念，要么是高中常识，要么在之前的期数讲过，要么本期当场讲清。不够就加铺垫，宁可多一期。对着 `docs/concepts.yml` 查；只"点过名"的不算讲过。`tools/check_prereq.py` 查的是 `meta.yml` 里登记的概念，脚本里实际用了什么要审核者自己数。
8. **一期一个想法。** 新术语不超过 3 个；数一数，超了就拆。
9. **让观众自己想一步。** 至少有一处停下来让观众先猜，再揭晓。

另查两本账：`docs/promises.md` 里标明本期要还的账还了没有；之前讲过的概念，本期的说法和 `concepts.yml` 的 `said` 是否一致。

输出：按严重程度排序的问题清单，每条给出原句、问题、改写建议；最后单列本期新许的愿和新引入的概念。

## 审核三：事实核查（`fact-checker`，独立于主笔）

写稿的人不核实自己。事实核查**先只看脚本**，自己列出全部事实性说法、逐条查证、复算模型数字，做完之后才打开主笔的 `facts.md` 对比。主笔漏列的说法单独列出。画面做完后再对着联系表查第二遍。

## 画面与英文版

- 画面：`silent-viewer`（只看联系表，不看脚本）加事实核查第二遍，见 `docs/directing.md` 第 8 节。
- 英文版：`en-freshman-native`、`en-freshman-nonnative`（只给英文脚本）加 `fidelity-reviewer`（对照中文定稿）。

## 通过标准

- 两个新生的复述都抓住了核心，且没有误解；路过的新生允许有"听不懂但不影响理解这一期"的地方，不允许有"听不懂就跟不上"的地方；
- 费曼审核没有"说错"（第 5 条）或"前置不闭合"（第 7 条）类问题；
- 事实核查没有 ❌；⚠️ 和 ❓ 逐条改写或删去，`facts.md` 全部 ✅；
- 其余问题作者逐条处理或写明不改的理由。

## 记录

- 讲法审核记在该期 `reviews/feynman.md`，事实核查记在 `reviews/factcheck.md`。
- 每份记录开头写明：审核日期、各 agent 的版本号（提示词正文第一行）、审的是脚本哪一版。
- 审核后更新两本账：新概念进 `concepts.yml`，新许的愿进 `promises.md`。
