## 1. 整体方案

**保留**：主线函数、四问题地图、玩具细胞、费曼审核、代码生成、数字由模拟驱动、双语同步、事实清单。第 1 期证明这套能跑通。

**要改的地方**

1. **节奏要有缓冲。** 每周一期、双语、3 年，等于 300 多条视频。现在是做完一期发一期，任何一周出问题就断更。建议：
   - 手里常备 2–3 期已定稿的存货；
   - 脚本按"弧"成批写（一次写 3–4 期），前置闭合在一个弧里一起检查更可靠；
   - 每圈结束停更 1–2 周，用来抽组件、复盘、补欠账。
2. **确认关卡从每周 6–7 个减到 3 个。** 现在脚本、试听、联系表、成片、英文稿、发布都要你确认。建议合并成：①脚本 + 分镜；②中英成片；③发布许可。试听和联系表只在自动检查或审核报出问题时才拿给你。
3. **加"动手"这条腿。** 第 1 期说"以后你会亲手算"，费曼式的理解也确实要自己动手。建议做一个网页版玩具细胞实验台（GitHub Pages）：点一下关掉基因、拖滑块加药，柱子按同一套方程变化。每期思考题都可以在上面验证。渲染本来就是 HTML + JS，成本不高。
4. **观众回流。** 发布后第 14 天看留存曲线和评论，写 `episodes/epNNN/retro.md`，掉人最多的位置对回脚本的哪一句，结论进规则。每圈末出一期"答观众问"。
5. **事实会过期。** `facts.md` 给每条加"易变"标记和核对日期；易变条目（如"深度模型没超过简单基线"）每半年重查一次，变了就出修订期。
6. **系列要有自己的家。** 系列会话在 `~/Projects/virtual-cell-series` 下开，长期约束（音频不入库、提交信息的规则、发布需明确许可、标题含"虚拟细胞"等）写进仓库的 `CLAUDE.md`，不再只存在另一个项目的记忆里。

## 2. 核心思想

### 2.1 一句话要会"升级"

现在的一句话是单个细胞、确定性、没有时间。它在低分辨率下是对的，但领域里真正预测的东西比这多。建议把"这句话每圈升级一次"做成系列的明线，每次升级就是一圈的收尾：

| 版本 | 何时 | 一句话 |
|---|---|---|
| v1 | 第 1 期（已发布） | 细胞的状态 + 你做的事 → 它会变成什么 |
| v2 | 第 1 圈末 | 加上"多久之后"和"一群细胞"：因为量一次细胞就没了，预测的是一群细胞的样子 |
| v3 | 第 2 圈末 | "状态"换成实际量得到的东西（主要是 RNA 读数），它和真正的状态隔着一层 |
| v4 | 第 3 圈末 | 这个函数有两种来历：按规则写出来，或从数据里学出来 |
| v5 | 第 4 圈末 | 要在没见过的情况下也对，要说出有几分把握，还要比最笨的办法好 |

### 2.2 三条暗线（每期都问）

1. **这是机器的哪一块？**（地图定位，现有）
2. **我们怎么知道的？** 画面上每个数字、每个说法带一个来源标签，全系列只有四种：`设定的`（玩具）、`算出来的`、`测出来的`、`还不知道`。第 1 期已有"玩具细胞（我们设计的）""示意图"两个标签，这里把它补全成一套。
3. **最笨的办法能做到多少？** 凡是介绍一种预测方法，先给出什么都不学的办法能得几分。这是这个领域目前最重要的一课，也是本系列和别的科普最不一样的地方。

### 2.3 第 1 期的洞见要接着往下推

第 1 期：只看状态不够，还要知道规则。
往下一步（建议放进第 1 圈）：**规则看不见，只能靠扰动把它逼出来。** 两个接线不同的玩具细胞，静止时都是 1 / 1 / 1，只有动它一下才分得开。这解释了为什么整个领域在大规模做扰动实验，也让"扰动"从"我们想问的问题"变成"我们提问的工具"。

### 2.4 玩具细胞要有版本路线

三个基因的确定性模型撑不起测量噪声、细胞群体、机器学习这些内容。建议按大纲提前排好：

| 版本 | 新增 | 用在 |
|---|---|---|
| v0.1（现有） | 3 基因确定性方程 | 第 1–5 期 |
| v0.2 | 测量层：RNA 与蛋白分开、打碎才能量、计数噪声 | 测量几期 |
| v0.3 | 细胞群体：每个细胞略有不同 | "一群细胞" |
| v0.4 | 数据集生成器：扰动 × 剂量 × 组合 | 学函数、基线、泛化 |
| v0.5 | 10–20 个基因的网络 | 3 个基因不够用的地方（组合、没见过的基因） |

每个版本都必须通过"已发布数字"测试。

### 2.5 两本账

- **欠账表** `docs/promises.md`：对观众许过的每个愿，在哪期许的，在哪期还。第 1 期的四笔：亲手算出"一半"和"2 倍"；关基因的工具；"差不多 ≠ 一模一样"带来的难题；真实细胞不会降得这么干净。
- **概念账** `docs/concepts.yml`（替代现在 11 行的术语表）：每个概念在哪期引入、当时用的那句话、用的比喻和比喻在哪里失效、中英用词。第 1 期用了"推动 / 压住""图纸 / 工作副本"，术语表里都没有。有了它，前置闭合可以用脚本检查：每期声明"用到哪些概念""引入哪些概念"，用到的必须在更早的期数引入过。

## 3. 大纲 v2（螺旋式）

**为什么改。** v1 的顺序是先 15 期生物学和测量，再扰动，再模型，最后才讲检验。三个问题：
- 第 1 期刚让观众对"规则"产生兴趣，第 2 期就转去讲细胞零件，"亲手算"要等到第 23 期；
- 第 1 期思考题的答案（B 只到 1.6）要用"推动会饱和"解释，这本身就要讲规则怎么算；
- 检验排在最后，前沿课在一年内都没有合格的前置。

**怎么改。** 四个问题走四圈，每圈分辨率更高。第 1 圈全部在玩具细胞上完成，画面素材高度复用，正好是抽共享组件的时候。

### 第 0 圈 · 序章
1. 什么是虚拟细胞（已发布）

### 第 1 圈 · 用三个基因走完一整圈（约 10 期，只用算术）

| 期 | 标题 | 这期的一个问题 | 备注 |
|---|---|---|---|
| 2 | 那个"2"是怎么算出来的 | 规则怎么变成数字？ | 开头揭晓关掉 C：B 只到 1.6。生产和分解打平；推动会饱和。还第 1 笔账 |
| 3 | 从现在到以后 | "接下来"是多久之后？ | 一小步一小步往前算就是模拟；先后顺序 B→C→A；稳定下来和半路上的区别 |
| 4 | 反馈 | 药效减半，A 为什么没减半？ | A 的生产 ×0.5，A 只降到约 0.72（原第 6 期） |
| 5 | 一样的状态，不一样的细胞 | 只看状态，能分清两个细胞吗？ | 见 2.3 |
| 6 | 隔着一层看 | 我们量到的是柱子本身吗？ | RNA 与蛋白、打碎才能量、读数有噪声 |
| 7 | 一群细胞 | 量一次就没了，怎么比"之前"和"之后"？ | 对照的两群；预测的是一群。还第 3 笔账 |
| 8 | 不看规则，只看数据 | 能从实验记录里猜出这个函数吗？ | 用玩具细胞自己产生的数据拟合最简单的模型 |
| 9 | 最笨的办法 | 什么都不学能得几分？ | 基线：猜"什么都不变"、猜"平均变化" |
| 10 | 没见过的考题 | 背答案和真学会怎么区分？ | 留出没见过的扰动和组合；数据泄漏的最小例子 |
| 11 | 第一圈复盘 | 三个基因的玩具缺了什么？ | 一句话升级到 v2；答观众问；引出真实细胞 |

每期结尾留 20–30 秒"真实细胞里对应的是什么、哪里不一样"，免得观众觉得一直在玩具里打转。

**第 1 圈结束后解锁的前沿课**：凡是只需要"扰动、基线、泛化"就能讲清的工作，例如第 1 期事实清单 #1 那篇（深度模型没超过简单线性基线）。

### 第 2 圈 · 真实细胞的状态（约 15 期）

- 细胞里有什么：细胞的零件 → 中心法则 → 基因表达（同一套 DNA 为什么长出不同细胞）→ 调控网络（真实的箭头是怎么测出来的）→ 信号通路 → 细胞状态与命运
- 怎么测：测序 → 单细胞测序 → 细胞 × 基因矩阵 → 噪声与缺失 → **批次效应（新增：同样的细胞，两天测出来为什么不一样？）** → 多组学、成像与空间
- 怎么压缩：降维 → 表示学习
- 收尾：一句话升级到 v3

### 第 3 圈 · 真实的扰动与两条路（约 20 期）

- 扰动：种类、**剂量与时间（新增）** → CRISPR（还第 2 笔账）→ Perturb-seq → 药物筛选数据 → 组合扰动 → 数据集与图谱
- 机理路线：微分方程（真实版）→ 随机性 → 代谢网络 → 全细胞模型与最小细胞（合并为 1–2 期）→ 机理路线的天花板
- 数据路线：机器学习 → 神经网络 → 生成模型 → Transformer → 基础模型 → 扰动预测模型 → **先验知识（新增：没见过的基因，模型凭什么预测？）**
- 神经网络、生成模型、Transformer 各只排了一期，对新生很可能不够。按"前置不闭合就加期"处理，不压缩。
- 收尾：一句话升级到 v4

### 第 4 圈 · 检验与前沿（约 8 期）

基线（真实数据版）→ 评估陷阱 → **泛化的三种考法（新增：新扰动、新细胞、新组合）** → **有几分把握（新增：不确定度）** → 相关与因果 → **下一步该做哪个实验（新增：模型指导实验）** → **从细胞到人（新增：兑现第 1 期"在人体内是否有效是另一个问题"）** → 开放问题与学习路线。收尾：一句话升级到 v5。

### 前沿课

- 取消"每 3 期核心课插 1 期"的固定比例，改成**前置解锁**：维护候选池 `docs/frontier-pool.md`，每条标出需要哪些概念；概念都讲过了才能排期。
- 选题标准不变（必须改变了函数的某一部分），增加一条：必须能回答暗线 3，即"它比最笨的办法好多少，谁验证的"。
- 核心课约 54 期，加前沿课后第 1 年大致走完第 1、2 圈。

## 4. 导演设计（新建 `docs/directing.md`）

现状：有色彩语义、暗色讲解风格、节拍对到句子起点、"先猜"停 2 秒，但没有成文的导演规则，也没有分镜这一步。

### 4.1 每期的骨架

| 段 | 内容 | 规则 |
|---|---|---|
| 冷开场 | 揭晓上期思考题，或一个观众会猜错的现象 | ≤ 25 秒；不用"想象一下……"式开头（第 1 期新生反馈开场套路化） |
| 定位 | 本期的一个问题 + 地图上亮一格 | ≤ 5 秒，地图不念（新生反馈：像目录，想快进） |
| 现象 | 具体的东西：玩具细胞或真实数据 | 先有东西，后有名字。第 1 期是先给定义（第 2 节）再给现象（第 3 节），以后倒过来 |
| 先猜 | 停下来让观众猜 | 每期至少一次；停 2 秒 |
| 揭晓与原因 | 模拟驱动的动画 + 为什么 | 数字带来源标签 |
| 起名字 | 术语出场 | 每期 ≤ 3 个 |
| 类比 | 用了类比才有这段 | 必须有"在哪里失效" |
| 回到机器 | 这期补上了机器的哪一块 | 固定镜头，位置不变 |
| 收尾 | 一句话 + 思考题 | 思考题必须能在实验台上验证 |

### 4.2 画面规则

1. **一刻一个焦点。** 金色只给当前正在讲的那一个东西。
2. **画面字是关键词，不是旁白。** 已经有字幕了，画面标签中文 ≤ 12 字、英文 ≤ 7 个词。
3. **同一个意思永远用同一个动作。** 柱子升降 = 量变；箭头上跑的光点 = 影响在传递；变灰 = 关掉；紫色 = 人为干预；飞入 = "这个就是那个"；问号 = 请你猜。新动作先登记再使用。
4. **回忆旧内容时用原镜头。** 代码生成的好处是能把第 1 期的镜头原样调出来，观众一眼认得。
5. **不许长时间静止。** 任何一段画面静止不超过 6 秒。英文版比中文长约 30%（第 1 期 7.5 分钟对 5.8 分钟），同一画面被拉长，要单独检查。
6. **封面写反直觉的结果，不写题目。**"没碰 A，A 却翻倍了"这个做法固定下来。
7. **声音。** 目前只有人声。建议第 2–3 期试一次：用代码合成的提示音（柱子变化、揭晓），不加配乐，看留存有没有变化再决定。

### 4.3 分镜表（新增一步）

脚本通过后、写代码前，出一张表：`节拍 | 对应旁白句 | 画面上有什么 | 什么在动 | 数字从哪来`。和脚本一起给你审。

### 4.4 画面层的检查

| 检查 | 方式 |
|---|---|
| 文字溢出、压字（中英两种语言、所有节拍） | 脚本：在浏览器里量每个文字框是否超出容器。第 1 期英文版的溢出是肉眼发现的 |
| 静止过久、变化过密 | 脚本：逐秒比较帧差 |
| 画面数字与模拟一致 | 脚本：数字只能从 `data.js` 读，脚本和画面文字里出现的数字与模拟结果逐个比对 |
| 默片测试（新增） | agent：只给关键帧联系表，不给脚本，问"这期在讲什么，哪里看不懂" |
| 画面有没有说错（如药物穿过细胞核） | agent：事实核查者拿联系表做第二遍 |

现在 `workflow.md` 里引用的"避坑清单"在仓库外的技能里，公开仓库的读者看不到，要搬进 `directing.md`。

## 5. Agents 布局（新建 `agents/`）

### 5.1 原则

1. **能写成测试的不交给 agent。** 数字、溢出、读音比对、音量、前置闭合都是脚本。agent 只做需要判断的事。
2. **审核者只拿到他那个角色本来能拿到的东西。** 这条现在已经在做，继续保持。
3. **写的人不核实自己。** 现在脚本和事实清单出自同一个上下文。
4. **提示词入库。** 每个角色一个文件 `agents/<角色>.md`，带版本号；每期审核记录写明用的是哪一版。同时放一份到 `.claude/agents/`，任何会话都能按名字调用。
5. **模拟新生不等于真新生。** 模型装不出"不知道"，复述测试只能当弱证据。最有用的信号是它在揭晓前猜错了什么（第 1 期猜 B ≈ 2，说明悬念成立）。

### 5.3 成本

脚本阶段从 2 个审核 agent 增加到 4 个，画面阶段新增 2 个。新生和默片观众可以用便宜的模型；主笔、费曼审核、事实核查用最强的。

## 7. 落地顺序

1. **第 2 期开工前**：定大纲 v2 与第 2 期题目；加"已发布数字"测试；建欠账表；仓库加 `CLAUDE.md`；修第 6 节的矛盾。
2. **第 2–3 期**：启用分镜表、事实核查 agent、`check_numbers`、溢出检查；提示词入库。
3. **第 3 期后**：抽共享组件到 `design/`；建 `concepts.yml` 和前置检查；上线网页实验台。
4. **第 1 圈内**：攒出 2–3 期存货；第一次发布后复盘；找真新生看一期。
