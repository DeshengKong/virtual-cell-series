# 每期文件夹规范

命名：`epNNN-英文短名/`，例如 `ep001-what-is-a-virtual-cell/`。核心课和前沿课共用一个编号序列，在 `meta.yml` 里区分。

```
epNNN-name/
├── meta.yml          # 标题、类型（core / frontier / revision）、地图位置（①–④）、本期的一个问题和一句话、
│                     # introduces / uses（docs/concepts.yml 的 id）、配音记录、status、published、release 链接
├── script.md         # 中文定稿解说词（含〔画面提示〕和内部备注）
├── script.en.md      # 英文解说词：按意思改写，不是逐字翻译；每节行数与中文相同（画面节拍靠它对齐）
├── facts.md          # 片中每一个事实性说法 + 出处（DOI），逐条核实后才能定稿
├── storyboard.md     # 分镜表（docs/directing.md 第 7 节），和脚本一起过关卡 1；第 2 期起
├── i18n/
│   ├── zh.json       # 画面上所有文字（中文）
│   └── en.json       # 画面上所有文字（英文），键与 zh.json 一一对应
├── video/            # 本期动画渲染代码（一套代码出两种语言）
├── cues.zh.json      # 各语言配音的逐句时间，由 video/make_cues.py 生成
├── cues.en.json
├── reviews/          # feynman.md（讲法审核）、factcheck.md（事实核查）、关键帧联系表；写明审核 agent 的版本
├── publish.md        # 两个平台的标题、简介、章节、设置，以及发布记录
├── retro.md          # 发布后第 14 天复盘：观众在哪里走的、评论、对规范的修改建议
└── notebook.ipynb    # 观众可以自己运行的玩具细胞实验（不是每期都有）
```

不入库：`audio/`（配音）、`out/`（成片和封面）。

## 双语规则

- 中文先定稿；英文版按意思改写，逐行对应，用词以 `docs/concepts.yml` 的 `zh` / `en` 为准。
- 中英两版同一周做，同步发布（中文 B 站，英文 YouTube）。
- 动画代码里不写任何硬编码文字，一律从 `i18n/<lang>.json` 读取。
- 画面事件时间点由各语言配音的逐字时间（faster-whisper）分别生成：`cues.zh.json`、`cues.en.json`。
- 配音：Gemini TTS 的 Charon 声线，固定风格提示见 `docs/voice.md`；每期在 `meta.yml` 里记录，保证可复现。音频文件不入库。
- 英文版和中文版有意不同的地方（为英文观众加的例子、多说的一句话）记在 `script.en.md` 的内部备注里；多许的愿记入 `docs/promises.md`。

## 每期讲法（硬规则）

1. 只回答一个问题，结尾用一句话总结。
2. 顺序：冷开场（一个现象或一个问题）→ 定位（地图上亮哪一格）→ 现象 → **先猜** → 揭晓与原因 → 起名字 → 类比和它在哪里失效 → 回到机器 → 收尾。细则见 `docs/directing.md` 第 1 节。
3. 先讲概念，再给名字；模型名只作为例子出现。每期新术语不超过 3 个。
4. 开头用几秒标出"四问题地图"上的位置；结尾留一道用 `toycell` 算得出答案的思考题，下期开头揭晓。
5. 每个数字和说法带来源：设定的 / 算出来的 / 测出来的 / 还不知道。前沿内容区分"已证实""有争议""未知"。
6. 不使用论文原图，所有画面由代码重画。
7. 凡是画面上出现的模型数值（柱子高度、曲线），必须由 `toycell` 等代码的模拟输出驱动，不得按预设答案手绘。
8. 区分"规则已知，所以算得出来"和"规则未知，所以要学习并用实验检验"，不让观众以为画出网络就能预测一切。
9. 用到的每个概念必须是高中常识、之前讲过，或本期当场讲清（`tools/check_prereq.py`）。之前许过的愿到期要还（`docs/promises.md`）。
10. 介绍任何预测方法时，先说"最笨的办法能得几分"（第 9 期讲过基线之后必须做到）。
11. 第 1 圈（第 2–11 期）只用算术，不出现微积分记号。
